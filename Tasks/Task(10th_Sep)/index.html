The mental model

Four layers, four jobs.

Playwright feels like one API, but its reliability comes from clean ownership boundaries underneath.

01 / AUTHOR

Your test

Expresses a user journey with locators, actions, and web-first assertions. The test asks for fixtures; it does not manage browser cleanup.

  • Readable intent
  • Assertions that retry
02 / ORCHESTRATE

Playwright Test

The runner discovers tests, applies configuration and projects, creates fixtures, schedules workers, retries failures, and reports results.

  • Parallel worker processes
  • Project matrix and retries
03 / ISOLATE

Browser context

A fast, incognito-like profile. Cookies, storage, permissions, locale, and viewport live here. Each test gets a fresh context by default.

  • Cheap to create
  • Multiple users in one test
04 / EXECUTE

Browser process

Chromium, Firefox, or WebKit performs the real browser work. Pages and frames are the surfaces your test interacts with.

  • One API across engines
  • Headed or headless
One test run

From intent to evidence.

The runner owns the lifecycle, while the browser executes the commands. This is why setup and cleanup belong in fixtures and configuration.

Playwright Test is the conductor.

It turns configuration and test declarations into a controlled execution: projects, workers, fixtures, timeouts, retries, and reporters are all runner concerns.

npx playwright test --project=chromium --workers=4
Architecture in practice

Design for the system you have.

Most flaky tests are boundary problems: shared state escapes the context, or the test asks the runner to behave like a script.

01 / ISOLATE DATA

Make parallelism boring.

Give each test unique backend data, files, and accounts. Context isolation handles browser state, not your database or shared service.

02 / USE FIXTURES

Put lifecycle near ownership.

Use test-scoped fixtures for clean setup and worker-scoped fixtures for resources intentionally shared by one worker.

03 / PREFER LOCATORS

Describe the user surface.

Role, label, text, and test-id locators let Playwright auto-wait for actionable elements instead of relying on sleeps and brittle selectors.

04 / TRACE SELECTIVELY

Keep failure evidence.

On CI, trace on the first retry or retain traces on failure. The Trace Viewer connects actions to DOM snapshots, network, console, and source.
