Promise combinators

Promise.all waits for the whole team.

Use Promise.all when several operations are independent but every result is required before continuing.

AsyncawaitPromise.racenew PromiseCallback

All succeed, in input order

const checks = await Promise.all([
  checkLogin(),
  checkSearch(),
  checkCheckout()
]);

console.log(checks);

The operations start together. The returned array keeps the same order as the input array, even if the third operation finishes first.

One rejection rejects the combined Promise

If any operation rejects, Promise.all rejects, but it does not cancel the other operations. They keep running to completion, and a late rejection can surface as an unhandled rejection after your code has moved on. Use try/catch and give each operation deliberate error handling.

When every outcome matters

Use Promise.allSettled when you need a report containing fulfilled values and failures. Unlike Promise.all, it waits for every input to settle.

const outcomes = await Promise.allSettled(checks);
const failures = outcomes.filter(result => result.status === "rejected");

Playwright: arm the listener first

Browser events can fire during the trigger. Put the listener and action in the same Promise.all so the listener is ready before the click.

const [popup] = await Promise.all([
  page.waitForEvent("popup"),
  page.getByRole("link", { name: "Open report" }).click(),
]);

const [download] = await Promise.all([
  page.waitForEvent("download"),
  page.getByRole("button", { name: "Export" }).click(),
]);

The same listener-before-trigger shape works for page.waitForResponse().

Why it is faster

Three one-second operations take about one second together, rather than about three seconds when each one is awaited before starting the next. This demo measures the elapsed time so you can see the difference.
