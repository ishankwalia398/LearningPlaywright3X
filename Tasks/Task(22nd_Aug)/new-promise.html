Building asynchronous values

new Promise lets you define the finish line.

Use the Promise constructor when you need to wrap an operation that will call resolve on success or reject on failure.

The two outcomes

function deliverFood() {
  return new Promise(function (resolve, reject) {
    const foodReady = true;
    if (foodReady) {
      resolve("Pizza delivered");
    } else {
      reject(new Error("Order cancelled"));
    }
  });
}

A new Promise starts as pending. Call resolve(value) once for success or reject(error) once for failure. The Promise settles only once.

Best practice: reject with an Error object so the caller receives a useful stack and message.

Creating versus consuming

new Promise creates the asynchronous contract. The caller consumes it with .then/.catch or await. You usually create a Promise only when adapting a callback or another non-Promise API; built-in APIs already return Promises.
