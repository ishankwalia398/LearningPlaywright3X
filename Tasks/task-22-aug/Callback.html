The original async hand-off

A callback is a function you give to another function.

The receiving function calls your callback later, often after a timer, file read, or API response has finished.

A small callback flow

function fetchUser(callback) {
  setTimeout(function () {
    callback(null, { name: "Maya" });
  }, 700);
}

fetchUser(function (error, user) {
  if (error) return console.log(error);
  console.log(user.name);
});

The first callback argument is commonly an error. If it is null, the next argument contains the successful result. This is called the error-first callback convention.

Callback hell: nesting many dependent callbacks makes code harder to read and handle errors in. Promises and async/await flatten that flow.

Who controls when?

You pass the callback now, but the other function controls when it is called. That is useful for event listeners and older Node.js APIs, but it also means you must carefully handle errors and avoid calling the callback twice.

button.addEventListener("click", function () {
  console.log("The browser called my callback");
});
